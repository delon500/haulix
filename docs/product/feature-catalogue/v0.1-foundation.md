# Feature Catalogue — v0.1 Foundation

v0.1 ships 28 features: a fast, reliable downloader for Windows and macOS, with a browser extension for Chrome and Firefox. This catalogue explains each one, who it is for, and how we will know it works.

## How to read this

Each feature has the same five parts:

- **Tag line:** category, release version, tier (Free, Pro or Team), and ★ when it is a key differentiator.
- **What it is:** the feature in plain language.
- **User story:** "As a \[person\], I want \[goal\], so that \[benefit\]."
- **Scenario:** a short, concrete example of the feature in use.
- **Acceptance criteria:** testable conditions that must all pass before the feature counts as done.

The user stories reuse four personas so the catalogue reads consistently:

| Persona | Who they are | What they care about |
| --- | --- | --- |
| Maya | University student | Lectures and study material, limited storage, saving time |
| Diego | Video creator and editor | Source footage, high quality, large files, batch downloads |
| Priya | Remote worker who travels | Unreliable or metered connections, downloads that survive interruptions |
| Sam | Power user who runs a home server | Control, automation, privacy, keyboard-driven workflows |

Versions, tiers and ★ match the Features tab in `docs/planning/features.csv`.

## Core download engine

These four features are the foundation: speed, reliability, and access to files behind logins.

### 1. Multi-connection segmented downloads

**Core download engine · v0.1 · Free**

**What it is:** The app splits a file into several parts and downloads them at the same time over separate connections, then joins them back into one file. Servers often limit the speed of each connection, so several connections together are much faster.

**User story:** As Diego, I want large source files to download as fast as my connection allows, so that I spend less time waiting and more time editing.

**Scenario:** Diego downloads a 12 GB raw footage file. A browser would use one connection and take about 40 minutes. The app opens 8 connections and finishes in about 9 minutes.

**Acceptance criteria:**

- Files are split into up to 16 parts when the server supports partial downloads; users can set the maximum.
- When a server does not support partial downloads, the app falls back to a single connection without failing.
- The finished file is byte-for-byte identical to the original (verified by checksum in testing).
- Download speed is within 10% of aria2 on the same file and connection.

### 2. Pause, resume, and resume after crash, reboot or sleep

**Core download engine · v0.1 · Free**

**What it is:** Any download can be paused and resumed later from where it stopped. Progress is saved continuously, so a download also survives the app crashing, the computer restarting or going to sleep, or the internet dropping.

**User story:** As Priya, I want downloads to pick up where they left off after any interruption, so that I never lose progress or waste data re-downloading.

**Scenario:** Priya starts a 3 GB download on airport Wi-Fi. The connection drops at 70% as she boards. That evening at the hotel she opens her laptop and the download continues from 70%.

**Acceptance criteria:**

- Paused downloads resume from the last saved byte, not from the start.
- After a crash, forced shutdown or sleep, unfinished downloads appear with their progress intact when the app reopens.
- Progress is saved at least every 2 seconds while downloading.
- If a server does not support resuming, the app warns the user before they pause.
- Resumed downloads produce a correct, uncorrupted file.

### 3. HTTP/HTTPS and FTP/SFTP

**Core download engine · v0.1 · Free**

**What it is:** The app downloads from the common file transfer protocols: web links (HTTP and HTTPS) and file servers (FTP and SFTP). This covers almost every direct download on the internet and on company servers.

**User story:** As Sam, I want to download from web links and file servers in the same app, so that I don't need a separate FTP client.

**Scenario:** Sam pastes an SFTP link to a backup on his home server, enters his server username once, and it downloads alongside his normal web downloads in the same queue.

**Acceptance criteria:**

- HTTP, HTTPS, FTP, FTPS and SFTP links all download successfully.
- HTTPS certificates are checked; invalid certificates block the download with a clear warning the user can review.
- Redirects are followed, up to a sensible limit, with the final address shown in the download details.
- SFTP supports password and SSH key login.

### 4. Authentication: cookies, headers, browser cookie import

**Core download engine · v0.1 · Free**

**What it is:** Many files are only available after you log in to a site. The app can reuse your browser's login (cookies) so it can download those files too, and advanced users can add custom headers or a username and password.

**User story:** As Maya, I want to download lecture recordings from my university portal, which needs a login, so that I can watch them offline.

**Scenario:** Maya is logged in to her university portal in Chrome. She clicks a lecture video's download link. The extension passes her login session to the app, and the lecture downloads without her signing in again.

**Acceptance criteria:**

- Downloads started from the browser extension include that site's login cookies automatically.
- Users can import cookies from Chrome, Edge or Firefox for a site, after confirming which browser and site.
- Custom headers and basic username/password login can be set per download.
- Cookies and passwords are stored encrypted and never written to logs.
- When a login has expired, the error says so plainly and suggests logging in again in the browser.

## Media extraction

These six features let users save video and audio from websites, powered by the yt-dlp engine behind a simple interface.

### 5. Video and audio from thousands of sites

**Media extraction · v0.1 · Free**

**What it is:** Paste a link to a page with a video or audio track, and the app finds the actual media and downloads it. It works on thousands of sites, from large video platforms to news sites and course portals, because it uses yt-dlp underneath.

**User story:** As Maya, I want to save a video by pasting its page link, so that I can watch it later without needing an internet connection.

**Scenario:** Maya copies the link to a 20-minute explainer video. The app recognizes the link as soon as she pastes it, shows the title and thumbnail, and downloads it with one click.

**Acceptance criteria:**

- Pasting a supported page link shows the media's title, length and thumbnail within 5 seconds on a normal connection.
- Video and audio that a site serves as separate streams are merged automatically into one file.
- Unsupported links show a clear message, not a technical error.
- The app works on the 50 most-used supported sites in automated testing before each release.

### 6. Playlist, channel and profile downloads

**Media extraction · v0.1 · Free**

**What it is:** Download every video in a playlist, a channel or a profile from one link, with the option to pick only some of them.

**User story:** As Maya, I want to download a whole course playlist in one step, so that I have every lecture before exam week.

**Scenario:** Maya pastes a link to a 36-video course playlist. The app lists all 36 with sizes, she unticks the 4 she has already watched, and the other 32 are added to the queue in order.

**Acceptance criteria:**

- Playlist, channel and profile links list every item with its title, length and estimated size.
- Users can select all, select none, or tick individual items before downloading.
- Items keep their playlist order, and filenames can include their position number.
- Videos already downloaded are detected and skipped by default.
- Lists of 1,000+ items load without freezing the interface.

### 7. Quality and format picker with size estimates

**Media extraction · v0.1 · Free**

**What it is:** Before downloading, users choose the quality and format they want (for example, 1080p MP4 or 720p) and see roughly how big each option will be.

**User story:** As Diego, I want to pick the exact resolution and format before downloading, so that I get footage that fits my editing project without converting it later.

**Scenario:** Diego pastes a link and sees a list: 4K at 2.1 GB, 1080p at 650 MB, 720p at 310 MB. He picks 4K for a shot he will crop, and 720p for reference clips.

**Acceptance criteria:**

- All qualities the site offers are listed with resolution, format and estimated size.
- Simple mode shows 3–4 clear choices (Best, 1080p, 720p, Audio only); advanced mode shows every available format.
- Users can set a default quality so most downloads need no choice at all.
- Size estimates are within 15% of the final file size for at least 90% of downloads.

### 8. Clip downloads (time ranges, chapters) ★

**Media extraction · v0.1 · Free · ★ Differentiator**

**What it is:** Download only part of a video, by choosing a start and end time or picking chapters, instead of the whole thing. yt-dlp can already do this, but almost no app makes it easy.

**User story:** As Maya, I want to download just the section of a 3-hour lecture that covers my exam topic, so that I save time, storage and data.

**Scenario:** Maya pastes a lecture link, drags the timeline handles to 1:12:00–1:22:00, and gets a 40 MB file instead of a 900 MB one.

**Acceptance criteria:**

- Users can set a start and end time by dragging handles or typing timestamps.
- When a video has chapters, users can tick one or more chapters to download.
- The clip starts and ends within 1 second of the chosen times.
- Only the needed part is downloaded where the site allows it, not the whole video then cut.
- Several clips from one video can be queued at once.

### 9. Audio-only extraction (MP3, M4A, Opus)

**Media extraction · v0.1 · Free**

**What it is:** Save just the audio from a video, as a common audio file, for podcasts, talks, interviews and music practice.

**User story:** As Priya, I want to save talks as audio files, so that I can listen on flights without using storage on video I won't watch.

**Scenario:** Priya picks "Audio only" on a 90-minute conference talk. Instead of a 1.2 GB video, she gets a 70 MB M4A file on her phone.

**Acceptance criteria:**

- Audio can be saved as MP3, M4A or Opus, with a choice of quality.
- The app downloads only the audio stream when the site offers one, to save data.
- Title, artist or channel, and cover art are added to the audio file automatically.
- Audio-only can be set as the default for particular sites or playlists.

### 10. Background auto-updating of extractors

**Media extraction · v0.1 · Free**

**What it is:** Websites change often, which breaks media downloading until the yt-dlp engine is updated. The app keeps yt-dlp up to date automatically in the background, so fixes reach users in hours, without waiting for a full app update.

**User story:** As Sam, I want site support to stay working without me updating anything, so that downloads don't suddenly break after a site changes.

**Scenario:** A major video site changes its player overnight and downloads start failing. The next morning, the app has already pulled the fixed yt-dlp version, and Sam's queued downloads complete without him noticing anything happened.

**Acceptance criteria:**

- The app checks for a new yt-dlp version at least every 6 hours, and immediately after a site-related failure.
- Updates download and install in the background, without restarting the app or interrupting active downloads.
- Every update is verified with a signature or checksum before it is used.
- If a new version causes failures, the app rolls back to the previous version automatically.
- Users can turn off auto-updates or choose a stable or nightly channel.

## Browser integration

These five features connect the app to the browser, where most downloads start. The extension never downloads media itself: it hands links to the app, which keeps it within browser store rules.

### 11. Chrome and Firefox extensions

**Browser integration · v0.1 · Free**

**What it is:** A small browser extension for Chrome and Firefox that connects the browser to the app. It is how every other browser feature in this section works.

**User story:** As Diego, I want the app connected to my browser, so that downloading feels like part of browsing rather than a separate chore.

**Scenario:** Diego installs the app. On first launch it offers to add the Chrome extension, opens the store page, and confirms the connection with a green tick once installed.

**Acceptance criteria:**

- Extensions are published in the Chrome Web Store and Firefox Add-ons.
- The app's first-run setup detects installed browsers and links to the right store page.
- The extension icon shows whether the app is connected, and explains how to fix it if not.
- The extension requests only the permissions it needs, each explained in the store listing.
- Extension and app keep working together when either updates first.

### 12. Automatic interception of downloads

**Browser integration · v0.1 · Free**

**What it is:** When the user clicks a download link in the browser, the app takes over the download instead of the browser, so it gets the app's speed and resume features.

**User story:** As Priya, I want every download I start in the browser to go through the app automatically, so that large files resume if my connection drops.

**Scenario:** Priya clicks "Download" on a 2 GB software installer. The browser's own download bar doesn't appear; the app opens a small prompt with the filename and size, and starts it with segmented downloading.

**Acceptance criteria:**

- Clicked download links are handed to the app instead of the browser's download manager.
- Users can set which file types and minimum sizes are intercepted (for example, skip files under 1 MB).
- Holding a modifier key (such as Alt) while clicking lets the browser download normally.
- Specific sites can be excluded from interception.
- If the app isn't running, the browser downloads normally, with no lost downloads.

### 13. Media detection overlay button

**Browser integration · v0.1 · Free**

**What it is:** When a page has a video or audio track the app can download, a small "Download" button appears near it. One click sends it to the app with the user's default quality.

**User story:** As Maya, I want a download button to appear on videos I'm watching, so that I can save them without copying and pasting links.

**Scenario:** Maya is watching a lecture on a course site. A small download button appears over the top corner of the player. She clicks it, picks 720p from a short menu, and the lecture appears in the app's queue.

**Acceptance criteria:**

- The button appears on supported media within 2 seconds of the media loading.
- It offers quick choices (default quality, audio only) and a link to open full options in the app.
- The button can be hidden per site or turned off globally.
- It never covers the video's own playback controls.
- On sites where downloading isn't possible (for example, DRM-protected streams), the button doesn't appear.

### 14. Right-click "download with app" and "download all links"

**Browser integration · v0.1 · Free**

**What it is:** Right-clicking a link, image or video gives a "Download with \[app\]" option. Right-clicking the page gives "Download all links", which lists every downloadable file on the page.

**User story:** As Sam, I want to grab every file linked on a page at once, so that I don't have to click through dozens of links one by one.

**Scenario:** Sam opens a page listing 60 PDF datasheets. He right-clicks and picks "Download all links". The app shows all 60 PDFs plus a few images; he filters to PDF only and queues them all.

**Acceptance criteria:**

- "Download with \[app\]" appears on links, images, video and audio.
- "Download all links" lists every link on the page with filename, type and size where known.
- The list can be filtered by file type and searched by name before queueing.
- Duplicate links on a page are listed only once.

### 15. Login/session passthrough via native messaging

**Browser integration · v0.1 · Free**

**What it is:** When a download starts from the browser, the extension securely passes the app the login session and details it needs (cookies, the referring page, browser identity) through the browser's native messaging channel. This is the mechanism behind "Authentication" in the core engine section.

**User story:** As Maya, I want downloads from sites I'm logged in to to just work, so that I never get "access denied" errors for files I can open in my browser.

**Scenario:** Maya clicks a download link on her university's file portal. The extension passes her session to the app, which downloads the file. Without the session, the portal would have returned a login page instead of the file.

**Acceptance criteria:**

- Downloads from the extension succeed on sites that require a login, wherever the same file opens in the browser.
- Only the cookies for the download's own site are passed, never cookies for other sites.
- Data passes through the browser's native messaging channel, not an open network port.
- Session data is used for that download only and is not kept after it completes, unless the user saves it.

## Queue and scheduling

These three features control the order and pace of downloads when several are waiting.

### 16. Multiple queues with priorities

**Queue and scheduling · v0.1 · Free**

**What it is:** Downloads wait in queues, and users can create several (for example, "Work", "Courses", "Overnight"). Each queue and each download can be given a priority, so urgent files go first.

**User story:** As Diego, I want urgent client files to jump ahead of my background downloads, so that I can start editing on deadline without pausing everything by hand.

**Scenario:** Diego has 40 reference videos downloading slowly in a "Research" queue. A client sends a file he needs within the hour. He drops it in the "Urgent" queue, which has top priority, and it gets the bandwidth first.

**Acceptance criteria:**

- Users can create, rename and delete queues; new downloads go to a default queue unless chosen.
- Priorities (High, Normal, Low) apply to queues and individual downloads.
- Higher-priority downloads start before lower ones and get more of the bandwidth.
- Each queue can be started, paused or stopped on its own.

### 17. Drag-and-drop reordering

**Queue and scheduling · v0.1 · Free**

**What it is:** Users change the order of waiting downloads by dragging them up or down the list, or move them between queues by dragging.

**User story:** As Maya, I want to drag the lecture I need next to the top of the list, so that it downloads first without changing any settings.

**Scenario:** Maya has 32 lectures queued in order. Tomorrow's seminar covers lecture 18, so she drags it to the top. It starts as soon as the current download finishes.

**Acceptance criteria:**

- Waiting downloads can be reordered by dragging, and the new order is saved immediately.
- Several downloads can be selected and dragged together.
- Downloads can be dragged into another queue in the sidebar.
- Keyboard alternatives exist (for example, move up, move down, move to top) for users who don't use a mouse.

### 18. Concurrency limits per queue

**Queue and scheduling · v0.1 · Free**

**What it is:** Users set how many downloads run at the same time, per queue and in total. Running fewer at once often finishes everything faster and keeps the connection usable.

**User story:** As Priya, I want to limit how many downloads run at once, so that my video calls stay smooth while files download in the background.

**Scenario:** Priya sets her "Background" queue to one download at a time. Her 20 files take a little longer overall, but her video meetings no longer freeze.

**Acceptance criteria:**

- Each queue has its own limit of simultaneous downloads (default 3), plus an overall limit across all queues.
- When a download finishes, the next waiting one starts automatically within 1 second.
- Changing a limit takes effect immediately, without restarting downloads.
- Limits on connections per server are respected so sites don't block the user.

## Power and resilience

These two features make sure downloads finish and nothing is lost when the computer misbehaves.

### 19. Prevent sleep while downloading

**Power and resilience · v0.1 · Free**

**What it is:** While downloads are running, the app stops the computer from going to sleep on its own, then lets it sleep normally once everything finishes.

**User story:** As Diego, I want to leave large downloads running overnight, so that they're finished in the morning instead of stopped when my laptop slept.

**Scenario:** Diego queues 60 GB of footage at 11 pm and walks away. Normally his laptop would sleep after 15 minutes. The app keeps it awake until the last file completes at 3 am, then allows sleep.

**Acceptance criteria:**

- The computer does not go to sleep automatically while any download is active, on Windows and macOS.
- Sleep is allowed again within 1 minute of the last download finishing or being paused.
- The display can still turn off; only system sleep is blocked.
- The setting can be turned off, or limited to when the computer is plugged in.
- Closing the laptop lid or choosing Sleep manually still works as normal.

### 20. Crash-proof state saving

**Power and resilience · v0.1 · Free**

**What it is:** The app constantly saves the state of every queue and download (what is waiting, what is done, how far each one got) in a way that can't be corrupted by a crash or power cut.

**User story:** As Priya, I want my queue to be exactly as I left it after a power cut, so that I don't have to find and re-add dozens of links.

**Scenario:** Priya has 25 files queued and 3 downloading when the power goes out. When she restarts, all 25 are still there, the 3 partial downloads resume from where they stopped, and finished files are still marked done.

**Acceptance criteria:**

- After a forced shutdown or crash, the queue, settings and download progress are restored on next launch.
- State is saved using atomic writes, so a crash mid-save never leaves a broken file.
- Partially downloaded files are checked on restart, and damaged parts are re-downloaded rather than the whole file.
- In automated testing, killing the app 100 times mid-download causes zero lost queues or corrupted files.

## Security and privacy

These two features set the trust promise from day one: the app is safe to run, and it doesn't watch its users.

### 21. Sandboxed handling of downloaded files

**Security and privacy · v0.1 · Free**

**What it is:** Everything the app downloads comes from the internet and could be harmful. The helper programs that process files (yt-dlp, ffmpeg, aria2) run with limited permissions, and the app never opens or runs a downloaded file by itself.

**User story:** As Sam, I want the app to treat every download as untrusted, so that a malicious file or website can't take over my computer through it.

**Scenario:** Sam downloads a video from an unfamiliar site whose file has been crafted to exploit a bug in a media tool. ffmpeg crashes while merging it, but because it runs with limited permissions, nothing else on Sam's computer is affected, and the app reports the failed merge.

**Acceptance criteria:**

- Helper programs run as separate processes with only the folder access and permissions they need.
- The app never automatically opens or runs a downloaded file; users always choose to.
- Filenames from websites are cleaned, so they can't write outside the download folder (for example, names containing "../").
- Files are downloaded under a temporary name and only renamed once complete and checked.
- A crash in a helper program fails that one download, never the whole app.

### 22. No telemetry by default; open source or open core ★

**Security and privacy · v0.1 · Free · ★ Differentiator**

**What it is:** The app sends no usage data, browsing data or download history to anyone unless the user opts in. The core is open source, so anyone can check that claim. Many free download managers bundle adware or tracking; this is a deliberate contrast.

**User story:** As Sam, I want proof that the app doesn't track what I download, so that I can trust it with my browser and my files.

**Scenario:** Sam reads the privacy page, then checks the network monitor on his firewall. Apart from yt-dlp update checks, which are listed and can be turned off, the app contacts no servers of its own.

**Acceptance criteria:**

- No analytics, usage data or download history is sent anywhere without the user opting in.
- Crash reporting is off by default and asks permission the first time a crash happens.
- Every network connection the app makes on its own (update checks, for example) is listed in the privacy policy and can be turned off.
- The installer contains no bundled third-party software or offers.
- The core engine's source code is public, with reproducible builds planned.

## Platforms, UX, notifications and accessibility

These five features decide where the app runs, how it looks and talks to users, and who can use it.

### 23. Desktop: Windows and macOS

**Multi-device and remote · v0.1 · Free**

**What it is:** The first release runs on Windows and macOS, the two largest desktop markets. Linux follows in v0.5.

**User story:** As Diego, I want the same app on my Windows editing PC and my MacBook, so that I don't learn two different tools.

**Scenario:** Diego installs the app on his Windows desktop and his MacBook. Both look and work the same; only small details follow each system's conventions, such as where the menu sits.

**Acceptance criteria:**

- Runs on Windows 10 and 11 (x64 and ARM64) and macOS 10.15 or later (Apple Silicon and Intel).
- Installers are code-signed and notarized, so users see no "unknown publisher" or blocked-app warnings.
- Installs with no administrator rights needed where the system allows it.
- Installer size stays under 50 MB, including the bundled helper programs.
- The app updates itself, with the user's consent, on both systems.

### 24. Modern UI with light and dark themes

**UX and UI · v0.1 · Free**

**What it is:** A clean, modern interface that shows what matters (what's downloading, how fast, how long left) without clutter, in light and dark themes that can follow the system setting.

**User story:** As Maya, I want an app that looks clean and is obvious to use, so that I can download things without reading instructions.

**Scenario:** Maya opens the app for the first time. She sees an empty list with one clear prompt to paste a link. Her laptop is in dark mode, so the app opens in dark mode too.

**Acceptance criteria:**

- Light and dark themes are available, with a "follow system" option set by default.
- Each download shows its name, progress, speed, time left and status at a glance.
- A new user can download a file within 30 seconds of first opening the app, without help (tested with 5 or more first-time users).
- The window works at sizes down to 800 × 600 pixels.
- The interface responds to clicks within 100 ms, even with 1,000 items in the list.

### 25. Desktop notifications

**Notifications · v0.1 · Free**

**What it is:** The app sends a system notification when a download finishes, fails or needs attention, so users don't have to keep checking the window.

**User story:** As Priya, I want a notification when a download finishes or fails, so that I can get on with other work instead of watching progress bars.

**Scenario:** Priya starts downloading a large dataset and switches to writing a report. Twenty minutes later a notification says it's complete; she clicks it, and the file opens in its folder.

**Acceptance criteria:**

- Notifications appear for finished downloads, failed downloads, and downloads that need input (for example, a login).
- Clicking a notification opens the file's folder or the relevant download in the app.
- When many downloads finish together, they're grouped into one notification rather than dozens.
- Each notification type can be turned on or off, and the app respects the system's do-not-disturb mode.

### 26. Screen reader support and keyboard navigation

**Accessibility and localization · v0.1 · Free**

**What it is:** The app works fully with screen readers (such as NVDA, JAWS and VoiceOver) and can be used entirely with a keyboard, so people with visual or motor impairments can use it.

**User story:** As a user who is blind, I want every part of the app to be announced by my screen reader, so that I can manage downloads independently.

**Scenario:** A screen reader user tabs to the download list. Each item is read out as "Lecture 4, 62 percent, 3 minutes left." They press Space to pause it and hear "Paused."

**Acceptance criteria:**

- Every button, field and list item has a clear accessible name that screen readers announce.
- Every action can be done with the keyboard alone, with a visible focus outline at all times.
- Download progress changes are announced at sensible intervals, not on every percentage point.
- The app meets WCAG 2.1 AA for keyboard access and screen reader support.
- Testing is done with NVDA on Windows and VoiceOver on macOS before each release.

### 27. Adjustable font sizes and high-contrast mode

**Accessibility and localization · v0.1 · Free**

**What it is:** Users can make text larger, and switch on a high-contrast theme, so the app is comfortable for people with low vision or in bright environments.

**User story:** As a user with low vision, I want larger text and stronger contrast, so that I can read download details without straining.

**Scenario:** A user with low vision raises the app's text size to 150% and turns on high contrast. The layout adjusts, nothing is cut off, and all text and icons stand out clearly against the background.

**Acceptance criteria:**

- Text size can be set from 100% to 200%, and the layout adapts without text being cut off or overlapping.
- The app follows the system's text size and high-contrast settings by default.
- All text meets WCAG 2.1 AA contrast ratios (at least 4.5:1) in every theme; the high-contrast theme exceeds them.
- Status is never shown by color alone; it always has a label or icon too.

### 27a. Download history

**Library management · v0.1 · Free**

**What it is:** A permanent list of everything the user has downloaded: name, source link, date, size, folder and result. Users can search it, open a file or its folder, copy the original link, or download something again. Several later features build on it, including duplicate detection (32), private mode (52) and history sync (77).

**User story:** As Maya, I want to search everything I've downloaded, so that I can find a lecture from weeks ago without remembering which folder it went to.

**Scenario:** Maya remembers downloading a genetics lecture last month but not its name. She types "genetics" in the history search, sees it listed with its date and folder, and clicks "Open folder".

**Acceptance criteria:**

- Every finished, failed and cancelled download is recorded with name, source link, date, size, folder and result.
- History can be searched by name or link and filtered by date, type, site and result, returning results within 200 ms for 100,000 entries.
- Each entry offers: open file, open folder, copy link, download again, and remove from history.
- If a file has been moved or deleted, the entry says so instead of failing silently.
- Users can clear all history or entries older than a chosen age; private-mode downloads (feature 52) are never recorded.
